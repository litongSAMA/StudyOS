# StudyOS 测试用例集

> 对应提交要求 **（4）用例集：至少提交 10 条测试用例，覆盖正常场景、异常场景和边界场景**。
> 本文档给出 **30 条用例**（正常 12 · 异常 10 · 边界 8），每条都给出「前置条件 → 操作步骤 → 预期结果 → 自动化依据」，
> 并与仓库中真实存在的自动化用例逐条对应，可复跑验证。

| 项目 | 内容 |
| --- | --- |
| 被测系统 | StudyOS · 面向学生的个人学习管理智能体（FastAPI + React/TS + SQLite/FTS5，本地优先单机部署） |
| 用例总数 | 30 条（正常 12 / 异常 10 / 边界 8） |
| 自动化用例规模 | 后端 **727 项通过 + 1 项按环境跳过**（pytest，含本文档引用的全部用例，编号 `TC-xx` 的「自动化依据」即用例名，可直接 `-k` 复跑） |
| 前端用例 | Web **103 项** / Mobile **99 项**（Node 内置 test runner，`npm test`） |
| 测试环境 | Windows 11 + Python 3.14 + `.venv`（`requirements.txt` 精确锁定）；测试库为临时目录，强制离线规则引擎、关闭 OCR |

**回归测试绝不读写 `backend/data/studyos.db` 与 `data/files`（真实学习数据）**，不联网、不加载 OCR 模型，结果确定可复现。

## 2. 正常场景（12 条）

### TC-01 资料入库 → 结构化标签 → DDL 一次完成（主链路）
- **类型**：正常（核心业务链路）
- **前置条件**：后端已启动，数据为空库（或已灌入演示数据）；未配置 LLM Key（离线规则引擎）。
- **操作步骤**：
  1. `POST /api/agent/extract`，`text = "操作系统第三次作业：实现银行家算法，提交实验报告，11月20日 23:59 截止"`，`course_hint="操作系统"`。
  2. 核对返回的 `tasks[]`（含 `due_at`）与 `materials[]`（含课程/类型/标签）。
  3. `POST /api/agent/apply` 提交同一批次（带 `Idempotency-Key`）落库。
  4. `GET /api/tasks/upcoming?hours=720` 与 `GET /api/materials` 复核。
- **预期结果**：一次录入同时得到 1 条 DDL 任务（截止时间归一到 `23:59`）与 1 条资料（自动挂课程「操作系统」、类型「作业」、关键词标签）；落库后任务出现在提醒轮询中；同一 `Idempotency-Key` 重复提交不产生第二条（读取回执）。
- **自动化依据**：`test_agent_extract.py::test_extract_apply_full_chain`、`test_agent_integration.py::test_host_orm_index_and_undo`

### TC-02 中文时间表达归一化（含学期锚点换算）
- **类型**：正常
- **前置条件**：设置全局学期锚点 `semester_start=2026-09-01`（或课程级 `start_date`）。
- **操作步骤**：依次提交 `2025-11-30`、`11.30`、`11月30日`、`下周五 23:59`、`第12周周三下午2点`、`三天后`、`明天晚上10点`、`今晚24:00`、`中午12点半`。
- **预期结果**：全部解析为合法 ISO 时间；`今晚24:00` 跨天落到次日 00:00；`第12周周三下午2点` 按锚点换算为正确日期；无锚点时「第N周」类表达明确提示需要学期锚点而**不猜测**。
- **自动化依据**：`test_agent_extract.py::test_time_expression_normalization`、`test_week_expression_needs_semester_anchor`、`test_week_expression_with_global_semester_anchor`、`test_week_expression_with_course_anchor`

### TC-03 课表导入：南理工教务系统 .xls 版式端到端
- **类型**：正常（真实场景回归）
- **前置条件**：拿到南京理工大学「学生个人课表」.xls（BIFF8，行标签为「第一大节…第五大节」，周次写作 `4-6,8-18[周]`，教师带职称括注，教室为「Ⅳ-A103」）。
- **操作步骤**：`POST /api/courses/import/preview`（multipart `file`）→ 核对预览条目 → `POST /api/courses/import` 确认。
- **预期结果**：10 门课 / 17 个时段全部正确入库；课程名、教师（职称括注剥离）、地点（罗马数字楼号识别为教室）、周次（多段逗号串、单双周）逐格与源文件一致；同名课程自动合并、不重复建课；新课程自动配色；「第N周」类时间表达因开学日期自动推算而即刻可用。
- **自动化依据**：`test_course_import_sheet.py`、`test_course_import.py`、`test_course_import_formats.py`（含「大节→时刻」「`[周]` 周次」「职称剥离」「罗马数字教室」「空行分课」回归）

### TC-04 课表导入：八类来源统一解析
- **类型**：正常
- **前置条件**：同一份课表分别准备 Excel(.xlsx/.xls/.xlsm)、CSV/TSV、ODS、PDF、网页 HTML、Word .docx、.ics/.json、课表截图 八类文件。
- **操作步骤**：逐个走 `POST /api/courses/import/preview`，比较解析结果。
- **预期结果**：八类来源都还原为「行=节次 / 列=星期」同一套网格再解析，课程名/教师/地点/周次一致；回包带 `format_label`（「PDF 课表」「网页课表」「ODS 课表」「课表截图（AI 辅助）」等）；网页课表的 `rowspan/colspan` 合并单元格被正确展开；.ics 的 `RRULE/EXDATE` 展开为周次并排除节假日。
- **自动化依据**：`test_course_import_formats.py::test_grid_from_html_expands_merged_cells`、`test_preview_pdf_text_layer`、`test_grid_from_ods_reads_content_xml`、`test_preview_docx_file`、`test_preview_json_file`

### TC-05 资料文件全覆盖：110 种格式抽取
- **类型**：正常
- **前置条件**：准备 PDF / Word / Excel / PPT / ODT / EPUB / Notebook / HTML / RTF / SRT / 代码文件 / ZIP 等样本各一份。
- **操作步骤**：逐个 `POST /api/materials/upload`（multipart），核对回包的 `format{label,group,kind}`、`extracted_text_preview`、`text_chars`。
- **预期结果**：全部成功抽取正文；Excel/ODS 渲染成带表头的表格文本、PPT 含演讲者备注、字幕保留时间戳、代码附顶层定义摘要、ZIP 有界展开包内可解析文档；回包给出中文格式名与所属分组，前端据此渲染格式徽标与「抽取 N 字」提示。
- **自动化依据**：`test_upload_formats.py::test_upload_docx_with_table_and_deadline`、`test_upload_pptx_notes`、`test_upload_xlsx_sheets`、`test_upload_epub`、`test_upload_ipynb`、`test_upload_zip_expands_supported_entries`、`test_upload_tar_gz_expands_entries`

### TC-06 笔记提炼：重点/考点双模式（文件直传）
- **类型**：正常
- **前置条件**：准备 PDF 讲义、Word 笔记、Excel 复习提纲、PPT 课件与板书照片各一份；未配置 LLM Key（验证离线降级）。
- **操作步骤**：`POST /api/notes/refine-file`（multipart `file` + `mode=keypoints|exam`）→ 核对 `points[]`/`importance`/`engine`/`source_text` → 切换 `mode` 复用同一份 `source_text` 重新提炼 → `POST /api/notes` 保存。
- **预期结果**：五类文件均提炼出结构化要点（`high/medium/low` 重要度）；`engine` 显示离线规则引擎且**不编造原文没有的内容**；回包带 `format_label/text_chars/truncated/warnings[]` 与截断到 2 万字的 `source_text`，可核对原文、修正后重提炼；切换模式无需重新上传。
- **自动化依据**：`test_notes_file.py::test_refine_pdf_text_layer`、`test_refine_docx`、`test_refine_xlsx`、`test_refine_pptx`、`test_refine_file_saves_as_note`、`test_refine_file_image_uses_ocr`

### TC-07 检索：全文 / 语义 / 混合三种模式
- **类型**：正常
- **前置条件**：库中已有若干含「死锁」「银行家算法」等术语的资料；未配置 Embedding（走内置离线 TF-IDF）。
- **操作步骤**：`GET /api/search?q=死锁`；`?mode=semantic`；`?mode=hybrid`；再用 `?q=死锁&course_id=…&difficulty=hard&exam_focus=true&tags=考点&tag_mode=all` 组合过滤。
- **预期结果**：全文检索返回 bm25 排序 + 高亮 `snippet`；语义/混合模式返回 `scores` 与 `engine`；组合过滤**全部下推 SQL**，`X-Total-Count` 为过滤后真实总数（分页与计数在过滤之后，大库不丢结果）。
- **自动化依据**：`test_search.py`、`test_semantic.py`、`test_material_filters.py`、`test_material_archiving.py`

### TC-08 复习计划：DDL 倒排 + 掌握度加权 + 间隔重复
- **类型**：正常
- **前置条件**：某课程有 5 份资料（难度不同、含考试重点标记）与一场 14 天后的期中考试；已对部分资料评分。
- **操作步骤**：`POST /api/review/rate` 给资料打 `again/hard/good/easy` 四档；`POST /api/review/generate`（`hours_per_day=3`）生成计划；`GET /api/review/states` 查掌握度。
- **预期结果**：每天先排「今日到期的间隔复习」再排新学；未掌握资料（掌握系数 1.6）分配到更多时长，已掌握资料按间隔维持；首次学习自动预排 1/3/7 天检查点；间隔按 1→2→4→7→14→30 天阶梯拉长，`again` 使阶梯回退；逾期复习标红。
- **自动化依据**：`test_review_spaced.py::test_generate_schedules_due_reviews_first`、`test_generate_weights_by_mastery`、`test_generate_hours_shrink_with_mastery`、`test_apply_rating_lapse_resets_ladder`

### TC-09 进度预测与负载预警
- **类型**：正常
- **前置条件**：两门课各有考试 DDL 与若干未掌握资料；部分 DDL 集中在同一周。
- **操作步骤**：`GET /api/forecast?hours_per_day=3&days=21`。
- **预期结果**：每门课给出剩余学时、所需节奏、预计完成日、考试日预计掌握度与状态（`done/on_track/tight/at_risk`）；未来 21 天逐日负载（`ok/busy/overload`）；结构化告警覆盖超载、连续高负载、考试撞车；给出逐日掌握度曲线与近 7 天实际节奏对比；口径与复习计划共用同一套时长公式。
- **自动化依据**：`test_forecast.py`

### TC-10 错题归集 → 重练 → 掌握判定闭环
- **类型**：正常
- **前置条件**：库中有课程；错题章节/难度可留空（走自动规则抽取）。
- **操作步骤**：`POST /api/wrongbook`（题目/我的答案/正确答案/错因 + 标签）；`GET /api/wrongbook/practice?course_id=…` 取重练队列；对同一条 `POST /api/wrongbook/{id}/practice {"ok": true}` 两次；再对另一条先 `true` 后 `false`。
- **预期结果**：留空的章节/难度被自动抽取（如「第3章」「困难」）；连续答对 2 次自动置「已掌握」，答错清零回退「待攻克」；`GET /api/wrongbook/stats` 的总数/待攻克/已掌握/掌握率与操作一致。
- **自动化依据**：`test_wrongbook.py`

### TC-11 AI 自测出题 → 判分 → 统计
- **类型**：正常
- **前置条件**：某课程已有笔记（否则回落该课资料全文）；未配置 LLM Key（验证离线出题引擎）。
- **操作步骤**：`POST /api/quiz`（`qtype=mixed`，`n=10`）；选择题 `POST /api/quiz/{id}/answer {"index":0,"choice":"B"}`；问答题 `{"index":1,"ok":true,"answer_text":"…"}`；`GET /api/quiz/stats`。
- **预期结果**：生成 4 选项选择题 + 问答题（含解析），`engine=rule` 且题量达标；选择题**服务端自动判分**并即时返回解析；问答题记录回忆内容并自评；统计给出组数、已答题数、选择题正确率、问答通过率与按课程分布；同题重复作答按最后写入生效，`reset` 可清空重做。
- **自动化依据**：`test_restored_modules.py`、`test_health_stats.py`

### TC-12 导出：iCal / CSV / Markdown 三格式与增量导出
- **类型**：正常
- **前置条件**：库中有 DDL 任务、资料、复习计划；已开启登录保护（验证带令牌下载通道）。
- **操作步骤**：界面「数据导出」点击 9 个入口（3 类 × 3 格式）；直接导航 `GET /api/export/tasks/ical`；再 `?incremental=true` 导出一次；查 `GET /api/export/status`、`GET /api/export/records`。
- **预期结果**：9 个文件全部落盘（文件名 `studyos-tasks|materials|review` × `.ics/.csv/.md`）；iCal 为真 RFC 5545（`BEGIN/END:VCALENDAR`、稳定 UID、带 VALARM），CSV 带 UTF-8 BOM（Excel 中文不乱码），Markdown 为人可读勾选格式；增量导出只含自上次同类同格式导出以来的变更，导出历史与基线同步刷新；响应头给出 `X-Export-Count/Since/Until/Incremental`。
- **自动化依据**：`test_exports.py`、`test_export_incremental.py`、Web/Mobile `tests/download.test.mjs`（文件名解析 / `/api/api` 归一化 / 404 抛出 / 不可达指引）

## 3. 异常场景（10 条）

### TC-13 空文本 / 纯文本无任务：明确拒绝而非编造
- **类型**：异常
- **操作步骤**：`POST /api/agent/extract` 传空字符串；再传一段没有任何 DDL 的纯描述文本。
- **预期结果**：空文本 **422** 并给出中文原因；纯文本不产生任何 `tasks[]`（**绝不把整段原文当成一条 DDL**），只产出资料；界面提示下一步可做什么。
- **自动化依据**：`test_agent_extract.py::test_extract_empty_text_422`、`test_extract_no_task_for_plain_text`

### TC-14 损坏 / 加密 / 认不出的文件：给可执行的下一步
- **类型**：异常
- **操作步骤**：上传损坏的 .docx、加密的 ZIP 条目、7z/rar 压缩包、随机二进制、HEIC 图片（本机无解码器）、音视频文件。
- **预期结果**：各自给出**可操作的中文指引**而非「文件已损坏」这类无信息报错——7z/rar → 「先用工具解压再上传」；HEIC → 「先转 JPG/PNG」；音视频 → 「本机不联网、不能离线转写，可上传配套课件或粘贴文字」；未知二进制 → 转 PDF/TXT 指引；加密/超限压缩条目跳过并说明原因。
- **自动化依据**：`test_upload_formats.py::test_upload_7z_gives_actionable_guidance`、`test_upload_heic_without_decoder`、`test_upload_media_gives_actionable_hint`、`test_upload_unknown_binary`、`test_upload_damaged_docx`、`test_upload_image_without_ocr_keeps_guidance`、`test_notes_file.py::test_refine_file_media_guidance`、`test_refine_file_unknown_type`

### TC-15 课表文件解析失败：报错要能指导修正
- **类型**：异常
- **操作步骤**：分别上传损坏的 PDF、空 ODS、不含 `<table>` 的 HTML、旧版 `.doc`、无文本层且 OCR 不可用的扫描 PDF、HEIC 截图。
- **预期结果**：损坏 PDF → 明确「文件损坏/请重新导出」；空 ODS → 「表格为空」；HTML 无表格 → 指引用教务系统「打印」页另存；旧版 .doc → 「建议另存为 .docx」；扫描件无文本层 → 「改用文字版 PDF 或安装 OCR」；HEIC → 转换指引。全部为 422 且附下一步动作，不返回 500。
- **自动化依据**：`test_course_import_formats.py::test_preview_corrupt_pdf_gives_actionable_error`、`test_preview_empty_ods_gives_actionable_error`、`test_preview_html_without_table_gives_actionable_error`、`test_preview_legacy_doc_gives_save_as_hint`、`test_preview_heic_without_decoder_gives_conversion_hint`、`test_preview_scanned_pdf_without_ocr_engine`

### TC-16 课表导入并发抢建：预览后数据变化 → 409 重新生成
- **类型**：异常（并发一致性）
- **前置条件**：两台设备分别对「同一门新课」生成导入预览（都判定为「新建」）。
- **操作步骤**：设备 A `POST /api/agent/plans/{id}/apply` 成功；设备 B 用**同一份预览**执行 `apply`。
- **预期结果**：B 返回 **409** 并要求重新生成预览，**不会插入重复课程**；`checks` 对既有行比对整行快照、对新建行比对「同名是否已存在」；执行与撤销都要求 `Idempotency-Key`（同键同内容读回执、同键不同内容 409）。
- **自动化依据**：`test_agent_courses.py`、`test_agent_plans.py`

### TC-17 后端未启动 / 网络不可达：前端明确指引，不静默
- **类型**：异常
- **操作步骤**：停掉后端，点击任意导出入口与任意数据加载入口。
- **预期结果**：导出卡片就地显示「导出失败（DDL 任务 · CSV）：…」，全局红色横幅给出「无法连接后端 API…请确认已运行 `./start.sh`」，8 秒自动消失；**不出现假成功**、不出现空白页；重启后端即恢复。
- **自动化依据**：Web/Mobile `tests/download.test.mjs`（不可达指引用例）+ GUI 端到端复核（`docs/export-download-error-verified.png`）

### TC-18 登录保护：未登录收口与防爆破
- **类型**：异常（安全）
- **前置条件**：开启「登录保护」。
- **操作步骤**：不带令牌请求 `GET /api/materials`；带错误令牌请求；连续多次输入错密码；再请求 `/api/health` 与 `/api/share/{token}`。

## 7. 已知边界（如实说明，不计为"通过"）

1. 音视频**不做离线转写**（本机无语音识别），只给替代做法；HEIC 依赖系统解码器，缺失时给转换指引。
2. 「第N大节」按标准 12 节时间表换算（第五大节 = 9-10 节 19:00-20:40），个别学校作息不同需在预览里手改。
3. Web Push 已接入真实发送路径并自动验证发送契约/错误/竞态，但**未用真实设备订阅验证第三方推送实际送达**（需 HTTPS 与真实浏览器订阅）。
4. 外部 LLM/Embedding 未做真实服务商联调（离线规则引擎为默认验证路径，`engine` 字段如实标注）。
5. 跨设备离线队列通过 JSON 手动迁移（不自动后台发送）；附件须在目标设备重新上传。
6. 对话记录暂不跨独立服务器同步（同服务 Web/Mobile 可恢复历史）。
7. 登录保护限制的是**整个共享学习库**的访问，不做多租户隔离数据（账号=本机访问锁）。
