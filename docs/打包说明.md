### 两个容易踩的点

1. **`web/dist`、`mobile/dist` 是交付必需，请勿删除。**
   后端 `backend/app/api/main.py` 直接托管 `web/dist`，评审不装 Node.js 也能跑界面。
   删掉后接口仍正常、界面 404，问题不易发现。`.gitignore` 已在末尾显式保护这两个目录。
2. **`release/` 是产物区，不是源码。** 归档不进版本库（由 `scripts/build-release.ps1` 生成）。
   请不要把 zip 解压到项目根目录再交付——那样会在源码树里多出一份约 396 MB 的重复副本。

### 快速验证（评审最短路径）

**A. 免安装包路线（不装 Python / Node.js）**

1. 解压 `release/StudyOS-Windows-x64.zip`（得到 `StudyOS-Windows-x64/`）；
2. 双击其中的 `StudyOS/StudyOS.exe`；
3. 浏览器打开 `http://127.0.0.1:8800`；
4. 包内 `StudyOS/运行自检.cmd` 可跑一遍 40 项临时数据自检。

**B. 源码路线（需要 Python 3.10+；Node 仅在重新构建前端时需要）**

```bat
:: Windows：双击 scripts\start.bat（自动建 venv、按 requirements.txt 装依赖、起服务、开浏览器）
scripts\start.bat
```
```bash
./scripts/start.sh -d        # macOS / Linux，后台常驻；前台运行去掉 -d
./scripts/stop.sh            # 停止
```

灌入演示数据（合成数据，可重复执行）：

```bat
cd backend
.venv\Scripts\python.exe scripts\seed.py --reset
```

跑回归测试：

```bat
cd backend
.venv\Scripts\python.exe -m pytest tests -q
```

访问入口：`http://127.0.0.1:8800`（前端构建产物由后端单端口托管）、接口文档 `http://127.0.0.1:8800/docs`。
**默认无需登录、无需注册、无需任何 API Key**；不联网也能演示完整流程（内置离线引擎）。
可配置的环境变量见根目录 `.env.example`。

## 2. 相对开发目录做了什么调整

打包只做「删减与重排」，**未修改任何一行业务源码**。差异如下：

| 调整 | 内容 | 原因 |
| --- | --- | --- |
| 排除 | `backend/.venv/` | 本机 Python 虚拟环境不可跨机器复用；`scripts/start.bat` / `scripts/start.sh` 会按 `backend/requirements.txt` 自动重建 |
| 排除 | `web/node_modules/`、`mobile/node_modules/` | 依赖目录，`npm install` 可重建；`web/dist`、`mobile/dist` 已随包提供，无需构建即可运行 |
| 排除 | `backend/data/`（`studyos.db`、上传附件、`vapid_keys.json`） | **本机运行数据与私钥**，不应交付。首次启动会自动建空库并重新生成 VAPID 密钥；需要演示数据时跑 `scripts/seed.py --reset` |
| 排除 | `__pycache__/`、`.pytest_cache/`、`pytest-cache-files-*`、`tmp-pytest/`、`.testtmp/`、`jieba.cache`、`*.pyc` | 运行/测试产生的缓存与临时文件 |
| 排除 | 根目录的历史 zip 与已解压副本 | **同一份产物不重复保存**：交付包里只有 `release/StudyOS-Windows-x64.zip` 这一份 |
| 排除 | `logs/` 运行日志 | 运行时产生；目录以 `.gitkeep` 占位保留 |
| 保留 | `web/dist`、`mobile/dist` 预构建产物 | 让评审无需 Node.js 即可直接运行界面（**请勿删除**） |
| 新增 | `release/SHA256SUMS.txt`、`docs/打包说明.md`、`backend/data/.gitkeep`、`logs/.gitkeep` | 校验与说明；占位目录保证「解压即用」 |

`backend/data/` 被排除后**无需手工创建**：`backend/app/infra/config.py` 在导入时会执行
`settings.data_dir.mkdir(parents=True, exist_ok=True)`，首次启动自动建目录与空库。

## 3. 打包完整性校验

- **归档与解压内容一致**：`release/StudyOS-Windows-x64.zip` 内 5500 个文件与打包时的解压副本
  逐文件比对，**缺失 0 个、尺寸不一致 0 个**（两个解压副本之间也已逐文件 SHA256 比对为完全相同）。
- **禁用内容扫描**：包内无 `node_modules`、`.venv`、`__pycache__`、`.pytest_cache`、
  `pytest-cache-files-*`、`tmp*` 目录，无 `.pyc/.pyo/.db/.log` 文件，无本地数据库与附件。
- **可复核**：在 `release/` 目录下执行（Windows / macOS / Linux 均可）：

```bash
# 校验交付归档未被传输损坏
sha256sum -c SHA256SUMS.txt          # macOS: shasum -a 256 -c SHA256SUMS.txt
# 期望输出：StudyOS-Windows-x64.zip: OK

# 归档内部的逐文件校验（解压后在解压目录执行）
sha256sum -c StudyOS/SHA256SUMS.txt
```

## 4. 测试现状（如实说明）

`backend/tests/` 下 48 个活跃用例文件。当前实测（Python 3.13 + 锁定依赖）：

```
679 passed, 24 failed, 60 errors, 1 skipped
```

失败与错误的来源已定位，**不是打包造成的**：

| 类别 | 数量 | 原因 |
| --- | --- | --- |
| 环境限制类 error | 60 | 用例需在系统临时目录建库/建文件，本机沙箱环境拒绝写入（`PermissionError`）。用 `STUDYOS_TEST_TMP=<可写目录>` 指定可写临时目录可消除这一整类 |
| 功能缺口类 failed | 24 | 用例描述的接口/字段与当前实现不一致（如 `test_quiz.py` 引用不存在的 `app.quizgen`、`test_material_file.py` 期望的文件服务路由缺失、`test_focus.py` 文案断言不符） |

`backend/tests/quarantine/` 内另有 4 个文件**已隔离**：它们引用了本仓库从未存在过的模块
（`app.report`、`app.ssrfguard`、`app.timetable_grid`、`app.models.User`），会让 pytest 在
**收集阶段**直接中断整轮测试（`Interrupted: 4 errors during collection`）；隔离后测试才能完整跑完。
详见该目录 `README.md`。

> 结论：这批失败是**待偿还的测试债务**，不是"测试全绿"的状态。本文档不再声称通过数，
> 历史版本中"727 passed"的说法与当时的仓库状态不符。
